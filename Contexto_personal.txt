A. **COMMIT ÚNICO:** por cada iteración de trabajo se prepara y verifica el conjunto completo de cambios de todos los archivos relacionados y se publica exactamente un commit final. B. **CHECKPOINT OBLIGATORIO:** antes de pausar, terminar una sesión/iteración, transferir el trabajo, cerrar un sublote o detenerse por un bloqueo, agregar un checkpoint acumulativo al archivo de contexto real existente. C. **PUERTA DE INICIO:** antes de modificar cualquier archivo, leer el contexto completo, la metodología completa, el plan vigente y el último checkpoint; verificar repositorio, rama de trabajo, rama base y HEAD de ambas ramas. El SHA final se confirma consultando el HEAD de GitHub y se comunica en el reporte de cierre.

E. **VERIFICACIÓN:** antes del único commit revisar el diff total y confirmar que todos los cambios relacionados estén incluidos, que no existan cambios ajenos, que el historial previo se conserve y que la rama base permanezca intacta. Después comprobar que el commit incluye el checkpoint y todos los archivos de la iteración.

- Regla: cada tarea debe cerrarse con un único commit que incluya todos los archivos modificados por esa tarea, tanto código como documentación/registros autorizados.
- No crear un commit por archivo. Primero reunir y revisar el conjunto completo de cambios de la tarea; después incorporarlo en un único commit.
- No mezclar en un commit cambios de tareas distintas. Cada tarea independiente tendrá su propio commit.
- El mensaje debe identificar la tarea. Antes de actualizar la rama, verificar que el commit contiene todos los archivos previstos, no incluye cambios ajenos y conserva los registros anteriores.
- Si la herramienta bloquea la creación del árbol, commit o actualización de la rama, no dividir la tarea en commits parciales: mantener la rama intacta, informar el bloqueo y buscar un método autorizado para el commit único.
- Esta regla complementa las reglas existentes de METODOLOGIA_DESARROLLO.md; no elimina ni sustituye ninguna regla ni registro histórico.

# REGLA PRIORITARIA Y OBLIGATORIA: UN SOLO COMMIT CON TODOS LOS CAMBIOS

Esta regla se debe leer y cumplir antes de iniciar cualquier operación Git en este repositorio. Tiene prioridad operativa frente a interpretaciones ambiguas de expresiones como «commits modulares», «por lote» o «por tarea»:

1. **Un único commit al cerrar la tarea/iteración de trabajo:** reunir en ese commit todos los archivos modificados por la tarea o iteración completa. No crear commits intermedios durante la edición.
2. **PROHIBIDOS los commits atómicos o por archivo:** nunca crear un commit separado por cada archivo, ni dividir una misma entrega documental/código en varios commits para ir guardando avances.
3. Primero leer, analizar, editar y verificar todos los archivos involucrados. Después preparar el árbol completo y crear exactamente un commit que incluya el conjunto íntegro de cambios relacionados.
4. Si una auditoría contiene varias subtareas ejecutadas como una misma iteración y sus cambios forman una sola entrega, agrupar todos esos cambios en un solo commit. No fragmentar por archivo, carpeta, tipo de documento o fase interna.
5. Antes de confirmar, revisar el diff completo, comprobar que no falte ningún archivo, que no haya cambios ajenos y que el historial previo permanezca intacto. Luego crear un único commit y verificar su árbol y SHA.
6. Si GitHub, la API, una cuota o cualquier restricción impide crear ese commit único, detener la operación y conservar la rama sin commits parciales. No intentar sortear el bloqueo creando varios commits pequeños. Informar el bloqueo y solicitar/usar una vía autorizada que permita publicar el conjunto completo en un solo commit.
7. Esta regla no autoriza modificar archivos restringidos, saltar controles, reescribir historia, usar force push ni tocar la rama base. Los commits separados solo se permiten cuando el usuario autorice expresamente separar tareas independientes.
